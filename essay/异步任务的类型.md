# JavaScript 任务与微任务：理解事件循环顺序

适用范围：排查 Promise、定时器和界面更新的执行顺序；关键原则：同步代码先完成，随后清空微任务队列，下一轮才从任务队列取得工作；当前代码示例：下面同时安排 queueMicrotask、Promise.then 与 setTimeout；常见误区/边界：任务和微任务是常用概念，具体调度细节会因浏览器与 Node.js 运行时而不同；官方参考：[MDN 微任务指南](https://developer.mozilla.org/zh-CN/docs/Web/API/HTML_DOM_API/Microtask_guide)。

可以把一次事件循环粗略理解为：执行当前脚本或任务、排空微任务、浏览器按需要进行渲染，然后继续处理后续任务。不要把这套心智模型当成跨所有运行时完全一致的时间保证。

## 可运行的顺序示例

~~~js
console.log("A");

setTimeout(() => {
  console.log("task");
}, 0);

queueMicrotask(() => {
  console.log("microtask");
});

Promise.resolve().then(() => {
  console.log("promise reaction");
});

console.log("B");

// 输出顺序：A、B、microtask、promise reaction、task
~~~

Promise 的 then 回调与 queueMicrotask 都进入微任务队列，按入队顺序执行。setTimeout 的回调是后续任务，零延迟只表示“尽早排队”，不表示立即执行。

## 实践边界

await 在等待的 Promise 落定后会恢复到微任务阶段。若在微任务中不断继续安排新的微任务，后续任务和浏览器渲染可能被饿死；应把批量工作分段，必要时让出事件循环。

requestAnimationFrame 面向浏览器绘制时机，不应简单归类为普通定时器。服务器端还有自己的调度机制，尤其是某些专用队列的优先级不同；涉及跨端顺序时，应该在目标运行时写最小复现测试，而不是依赖记忆中的“固定顺序”。
