# preload、prefetch 与 preconnect：只提示关键资源

适用范围：优化首屏字体、关键脚本和下一跳页面资源；关键原则：preload 用于当前页面马上会消费的资源，prefetch 只是在浏览器空闲时提出下一步建议；当前代码示例：下面为字体、跨域连接和后续路由分别声明提示；常见误区/边界：资源提示不是强制下载命令，错误的 as 或 crossorigin 会造成重复请求；官方参考：[MDN rel=preload](https://developer.mozilla.org/zh-CN/docs/Web/HTML/Reference/Attributes/rel/preload)。

资源提示应来自真实的性能证据：先确认关键渲染路径，再为少量高价值资源添加提示。把所有资源都标为高优先级，会降低真正关键资源的收益。

## 为不同目的选择提示

~~~html
<link
  rel="preload"
  href="/assets/brand.woff2"
  as="font"
  type="font/woff2"
  crossorigin
>

<link rel="preconnect" href="https://fonts.example.com" crossorigin>

<link rel="prefetch" href="/assets/settings-route.js" as="script">
~~~

preload 表示当前页面很快会请求同一个资源。as 会让浏览器使用正确的请求优先级、内容安全策略和缓存键；字体等跨域资源还必须与实际使用时保持相同的 CORS 设置。

preconnect 只提前建立到某个来源的连接，适合数量很少且确定会访问的第三方来源。prefetch 的优先级通常较低，浏览器可能因网络状态、节流或省流策略选择不下载，因此不能把它当成导航正确性的前提。

## 验证而不是猜测

在浏览器网络面板检查资源是否只请求一次、是否在实际消费前到达，以及是否挤占了首屏图片或样式。不要为不会在当前页面使用的资源设置 preload，也不要用资源提示替代压缩、缓存、代码拆分或正确的加载顺序。

样式表仍应通过标准的 stylesheet 关系加载；若要减少阻塞，应从关键 CSS 的大小和拆分策略入手。更多关系类型可参考 [MDN link 元素](https://developer.mozilla.org/zh-CN/docs/Web/HTML/Reference/Elements/link)。
